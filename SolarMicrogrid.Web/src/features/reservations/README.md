# Reservations feature

Component 3 reservation list, detail, creation, update, cancellation, approval, and rejection UI. Staff creation uses the bounded `/api/users/eligible-prosumers` search. Create and reschedule read active stations and available slots from Member 2's APIs and never mutate slot capacity directly. Every lifecycle action uses the displayed server version plus one idempotency key per logical operation, blocks duplicate submits, reloads stale conflicts, queries current state before an uncertain-result retry, and ends in a dedicated server-refreshed summary. Lists and details revalidate on mutation signals, cross-tab storage events, focus/visibility changes, and a bounded polling interval. Lifecycle, eligibility, schedule, cutoff, overlap, capacity, and authorization decisions remain in the API.
